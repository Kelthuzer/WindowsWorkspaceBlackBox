# Windows Workspace BlackBox

Нативное Windows-приложение в трее: сохраняет расположение окон и папки Explorer, помогает восстановить рабочее пространство после перезагрузки или отключения питания.

**0.1.0 — предварительная версия для проверки на Windows.** Сборка и модульные тесты не заменяют проверку восстановления на реальном рабочем столе. Firefox и специальный адаптер MPC пока не реализованы.

## Установка

1. Откройте [последнюю успешную сборку](https://github.com/Kelthuzer/WindowsWorkspaceBlackBox/actions/workflows/build.yml).
2. Скачайте artifact **WindowsWorkspaceBlackBox-Setup-x64**, распакуйте ZIP и запустите `WindowsWorkspaceBlackBox-Setup-0.1.0-x64.exe`.
3. Установщик помещает приложение в `C:\Program Files\WindowsWorkspaceBlackBox`, создаёт пункты меню Пуск и по выбору — ярлык на рабочем столе.
4. Запустите приложение из меню Пуск. Вход в Windows запускает его через `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.

Windows x64, .NET поставляется внутри сборки; отдельная установка runtime не нужна. Установка требует администратора, ежедневная работа — нет. Сборка пока без цифровой подписи. Первый запуск выполните обычным ярлыком из меню Пуск. Если установка выполнена под другой административной учётной записью, этот запуск зарегистрирует автозапуск вашего пользователя; запись установившего администратора при необходимости удаляется из его HKCU. При удалении данные пользователя сохраняются. Если удаление выполняет другой администратор, автозапуск исходного пользователя может потребовать удаления из его HKCU вручную.

Portable EXE находится в отдельном artifact **WindowsWorkspaceBlackBox-Portable-x64**. При первом запуске автозапуск включён по умолчанию; его можно выключить в настройках. При перемещении portable EXE запустите его из нового расположения для обновления автозапуска.

## Использование

- `Сохранить состояние сейчас` — отдельный JSON, следующий автоматический снимок через пять минут.
- `Восстановить последний снимок` — при незавершённом восстановлении использует исходный снимок, сохранённый до перезапуска.
- `Выбрать снимок для восстановления` — выбор другого JSON из истории.
- `Отменить восстановление` — останавливает ожидание и дальнейшие запуски; уже открытые окна остаются.
- `Продолжить без восстановления` — снимает защиту старого снимка, текущая сессия становится основной.
- `Настройки` — автоматический/ручной режим, автозапуск, интервал, размер истории и список приложений.

В списке приложений один переключатель «Восстанавливать»: включён — открыть отсутствующие окна и вернуть расположение; выключен — не запускать и не перемещать окна. Проводник Windows всегда показан первым и включён по умолчанию; его переключатель управляет восстановлением папок. Снимки по-прежнему сохраняют сведения обо всех окнах.

При обновлении старый режим «только следить» становится выключенным. Steam, Telegram и FDM при переходе на новые настройки выключены; при желании их можно явно включить. Уже заданные разрешения запуска остальных приложений сохраняются.

В автоматическом режиме при входе в Windows приложение ждёт готовности Explorer, затем ещё 15 секунд даёт обычному автозапуску (например, Steam и Telegram) создать окна, выполняет восстановление, делает контрольный снимок и запускает таймер. При обычном ручном запуске EXE автоматическое восстановление не повторяется. В ручном режиме запись продолжается, а снимок до перезапуска защищён до восстановления или выбора «Продолжить без восстановления».

## Что сохраняется

EXE, имя процесса, доступная командная строка и разобранные аргументы, заголовок и класс окна, нормальная геометрия, состояние normal/minimized/maximized, монитор, DPI и foreground. HWND/PID — сведения исходной сессии, а не постоянная идентичность окна.

Explorer читается через Shell COM. Сохраняются реальные локальные/UNC-пути и доступные Shell namespace locations. Зарегистрированные вкладки сохраняются отдельными записями; при восстановлении могут стать отдельными окнами. Число доступных путей сверяется с окнами и обнаруженными хостами вкладок. Если COM не отдаёт все обнаруженные вкладки, снимок отклоняется с записью причины в журнал. **Поддержку всех вкладок на конкретной сборке Windows 11 ещё нужно проверить; считать её гарантированной нельзя.**

Обычные приложения восстанавливаются по EXE, классу, заголовку и командной строке, с назначением разных HWND разным сохранённым окнам. Уже сопоставленные процессы не запускаются повторно. Если программа хранит несколько документов в одном процессе и не умеет сама восстанавливать их, общий механизм не гарантирует возврат всех документов. Для таких программ позднее нужны адаптеры. Несохранённое содержимое, содержимое памяти, порядок Z всех окон, виртуальные рабочие столы и воспроизведение медиа не сохраняются.

Аргументы командных интерпретаторов не воспроизводятся: повтор `powershell -Command`, `cmd /c` и подобных команд мог бы повторно выполнить действие, а не открыть прежний терминал. Для обычных программ аргументы передаются напрямую через `ProcessStartInfo.ArgumentList`, без shell-конкатенации. Командные строки могут содержать приватные сведения — JSON и логи остаются локальными и никуда не отправляются.

Недоступные EXE, окна повышенных процессов, приложения Store, несовпавшие окна и папки отображаются как частичное восстановление. Защита исходного снимка при этом остаётся. UNC проверяется в отдельном процессе с ограничением времени, затем повторяется через интервалы 5/15/30/60 секунд. Нельзя гарантировать foreground, если Windows запрещает смену фокуса.

## Данные и отказоустойчивость

```text
%LOCALAPPDATA%\WindowsWorkspaceBlackBox\
  settings.json
  logs\YYYYMMDD.log
  snapshots\YYYYMMDD_HHMMSS_fffffff_000.json
```

По умолчанию 100 снимков. Каждый пишется сразу в новый файл с `CreateNew` и сбросом на диск, без `snapshot.tmp` и без rename. Совпадения имени получают числовой суффикс. Оборванный/некорректный JSON пропускается при поиске последнего валидного снимка. Коррекция системных часов не вызывает перезаписи. Очистка работает в фоне; защищённый исходный снимок занимает одно место в лимите истории. При частичном восстановлении новые снимки не снимают защиту источника.

Сбор выполняется дочерним процессом с тайм-аутом; зависший COM/WMI не блокирует трей. Выход/завершение сеанса отменяют выполняемую работу. На заблокированном экране автоматический сбор приостанавливается. Второй экземпляр трея блокируется mutex текущего сеанса.

## Сборка

На Windows с .NET 10 SDK и NSIS 3:

```powershell
dotnet restore WindowsWorkspaceBlackBox.slnx
dotnet build WindowsWorkspaceBlackBox.slnx -c Release --no-restore
dotnet test tests/WWBB.Tests/WWBB.Tests.csproj -c Release --no-build
dotnet publish src/WindowsWorkspaceBlackBox/WindowsWorkspaceBlackBox.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o artifacts/publish
New-Item -ItemType Directory -Force artifacts/installer
& "${env:ProgramFiles(x86)}\NSIS\makensis.exe" installer/WindowsWorkspaceBlackBox.nsi
```

GitHub Actions выполняет эти шаги на Windows и сохраняет installer, portable и результаты тестов. Шаги ручной приёмки: [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md).

## API

Использованы документированные [IShellWindows](https://learn.microsoft.com/en-us/windows/win32/api/exdisp/nn-exdisp-ishellwindows), [GetWindowPlacement](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowplacement) и Win32 window/monitor API. WinForms, C#, JSON; HTTP, служба Windows и драйвер не требуются.
