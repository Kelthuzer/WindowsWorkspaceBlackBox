# Windows Workspace BlackBox

Сохраняет список открытых папок Проводника и расположение окон, чтобы восстановить рабочее пространство после перезагрузки. Работает в трее Windows.

**Версия 0.1.0, предварительная.** Это восстановление окон и папок, а не резервная копия документов или памяти приложений.

## Скачать и запустить

Программа поставляется одним файлом **WindowsWorkspaceBlackBox.exe**, без установщика. .NET включён внутрь; отдельно устанавливать его не нужно. Нужна Windows x64.

Отдельного релиза в **Releases пока нет**. Скачать готовый EXE можно из **GitHub Actions**:

1. Откройте [список сборок](https://github.com/Kelthuzer/WindowsWorkspaceBlackBox/actions/workflows/build.yml).
2. Выберите завершённую успешную сборку ветки **main** с зелёной галочкой.
3. Внизу страницы в разделе **Artifacts** скачайте **WindowsWorkspaceBlackBox-x64**. Для скачивания может потребоваться вход в GitHub.
4. GitHub выдаёт артефакты ZIP-архивом. Распакуйте единственный файл `WindowsWorkspaceBlackBox.exe` в постоянную папку и запустите его обычным пользователем.
5. Найдите значок WWBB в трее. Windows может скрыть его под стрелкой **↑**. Главного окна при запуске нет — команды доступны по правой кнопке на значке.

Кнопка **Code → Download ZIP** скачивает исходники, а не готовую программу. В старых сборках встречаются архивы Setup и Portable; новые сборки содержат только EXE.

Для обновления завершите WWBB через **«Выход»** в трее, замените EXE и запустите снова. Настройки и снимки сохраняются. EXE пока без цифровой подписи.

## Первый запуск

1. Нажмите правой кнопкой на значок WWBB → **«Настройки»**.
2. Выберите, восстанавливать ли рабочее пространство автоматически после входа в Windows или по вашей команде.
3. В списке приложений включите те, которыми должна заниматься WWBB.
4. Выберите состояние окон после восстановления и нажмите **«Сохранить»**.
5. Откройте нужные папки и окна, затем выберите **«Сохранить состояние сейчас»** в меню трея.

Далее снимки делаются автоматически: по умолчанию каждые **5 минут**, хранятся **100 последних снимков**. Интервал и размер истории можно изменить.

Если список приложений пуст, сначала сделайте снимок и снова откройте настройки. Список заполняется из последнего снимка; кнопка **«Добавить EXE…»** позволяет добавить программу вручную. Проводник показан всегда.

## Какие приложения восстанавливать

В каждой строке один переключатель **«Восстанавливать»**:

| Положение | Поведение WWBB |
| --- | --- |
| **Вкл.** | Находит существующие окна, при необходимости запускает приложение и возвращает расположение окон. Для Проводника — открывает сохранённые папки и размещает их окна. |
| **Выкл.** | Не запускает приложение, не перемещает его окна и не считает его отсутствие ошибкой восстановления. |

**Проводник Windows находится в первой строке и включён по умолчанию.** Его тоже можно выключить.

При новом запуске без старых настроек обычные приложения выключены. При переходе со старых настроек режим «только следить» отключается; разрешения запуска остальных программ сохраняются, кроме Steam, Telegram и FDM — они при переходе выключены. Любое приложение можно затем включить вручную.

Если программа уже восстанавливает себя сама, оставьте её выключенной, чтобы WWBB не вмешивалась.

Переключатель управляет **восстановлением**, а не сбором сведений: снимки пока содержат информацию обо всех обнаруженных окнах.

## Состояние окон после восстановления

Общая настройка действует на включённые приложения и Проводник:

| Режим | Результат |
| --- | --- |
| **Как в снимке** — по умолчанию | Возвращает прежнее состояние: обычное окно, свёрнутое или на весь экран. |
| **Свернуть** | Восстанавливает окна свёрнутыми на панели задач. |
| **Показать** | Показывает окна в сохранённых обычных размерах и позициях, без раскрытия на весь экран. |

Если папки возвращаются свёрнутыми, в исходном снимке они могли быть свёрнуты. Выберите **«Показать»**, если хотите видеть их после восстановления независимо от сохранённого состояния. Сами снимки эта настройка не изменяет.

## Автосохранение и восстановление — разные вещи

- **Автосохранение** периодически записывает текущее рабочее пространство.
- **Автоматическое восстановление** возвращает его после входа в Windows. WWBB ждёт готовности Проводника, затем ещё 15 секунд для запуска остальных программ.
- **Восстановление по нажатию пользователя** означает, что окна открываются только по команде из трея. **Автосохранение при этом продолжает работать.**
- **«Запускать вместе с Windows»** управляет автозапуском самой WWBB.

Обычный запуск программы ярлыком не запускает автоматическое восстановление повторно.

## Команды в трее

| Команда | Что делает |
| --- | --- |
| **Сохранить состояние сейчас** | Создаёт новый снимок. Следующий автоматический снимок — через заданный интервал. |
| **Восстановить последний снимок** | Восстанавливает последний снимок либо защищённый источник незавершённого восстановления. |
| **Выбрать снимок для восстановления** | Позволяет выбрать более ранний JSON из истории. |
| **Отменить восстановление** | Останавливает дальнейшие действия; уже открытые окна остаются. |
| **Продолжить без восстановления** | Снимает защиту снимка до перезапуска и позволяет продолжить запись текущей сессии. |
| **Открыть папку данных** | Открывает настройки, снимки и журналы. |
| **Выход** | Завершает WWBB и останавливает автосохранение до следующего запуска. |

При частичном восстановлении исходный снимок остаётся защищённым от очистки. После успешного восстановления WWBB делает контрольный снимок.

## Известные ограничения и проблемы

- **Мерцание при автосохранении:** получено сообщение о кратком исчезновении чатов Telegram и перерисовке страницы Chrome. Причина пока не установлена; проблема не объявлена исправленной. Устранение смены значка WWBB в трее не является исправлением этого эффекта. Если мешает работе, временно завершите WWBB через «Выход»; автосохранение при этом остановится.
- **Вкладки Проводника:** сохранённые вкладки могут открыться отдельными окнами. Полная поддержка всех вкладок Windows 11 пока не гарантируется.
- **Содержимое приложений:** несохранённые документы, SSH-соединения PuTTY, вкладки браузера и воспроизведение медиа не восстанавливаются общим механизмом. Это зависит от возможностей самой программы; специальные адаптеры Firefox и MPC пока не реализованы.
- Окна программ с повышенными правами, недоступные EXE, приложения Store и сетевые папки могут восстановиться частично.
- Порядок всех окон друг над другом, виртуальные рабочие столы и возвращение фокуса не гарантируются.

Для сообщения об ошибке укажите действие и время, при необходимости приложите снимок и журнал из папки данных. Они могут содержать личные пути, заголовки окон и аргументы команд; проверьте содержимое перед публичной публикацией.

## Где хранятся данные

```text
%LOCALAPPDATA%\WindowsWorkspaceBlackBox\
  settings.json
  logs\YYYYMMDD.log
  snapshots\YYYYMMDD_HHMMSS_fffffff_000.json
```

Данные остаются локально: WWBB не отправляет снимки и журналы на сервер. Удаление программы не удаляет эту папку.

Программа использует эту папку данных и по умолчанию включает автозапуск. Его можно выключить в настройках. При переносе EXE запустите его из нового расположения, чтобы обновить запись автозапуска.

Если установщик запускался под другой административной учётной записью, первый обычный запуск регистрирует автозапуск для вашего пользователя. Запись в учётной записи администратора может потребовать ручного удаления.

<summary>Технические подробности и сборка из исходников</summary>

EXE, имя процесса, доступная командная строка и разобранные аргументы, заголовок и класс окна, нормальная геометрия, состояние normal/minimized/maximized, монитор, DPI и foreground. HWND/PID — сведения исходной сессии, а не постоянная идентичность окна.

Explorer читается через Shell COM. Сохраняются реальные локальные/UNC-пути и доступные Shell namespace locations. Зарегистрированные вкладки сохраняются отдельными записями; при восстановлении могут стать отдельными окнами. Число доступных путей сверяется с окнами и обнаруженными хостами вкладок. Если COM не отдаёт все обнаруженные вкладки, снимок отклоняется с записью причины в журнал. **Поддержку всех вкладок на конкретной сборке Windows 11 ещё нужно проверить; считать её гарантированной нельзя.**

Обычные приложения восстанавливаются по EXE, классу, заголовку и командной строке, с назначением разных HWND разным сохранённым окнам. Уже сопоставленные процессы не запускаются повторно. Если программа хранит несколько документов в одном процессе и не умеет сама восстанавливать их, общий механизм не гарантирует возврат всех документов. Для таких программ позднее нужны адаптеры. Несохранённое содержимое, содержимое памяти, порядок Z всех окон, виртуальные рабочие столы и воспроизведение медиа не сохраняются.

Аргументы командных интерпретаторов не воспроизводятся: повтор `powershell -Command`, `cmd /c` и подобных команд мог бы повторно выполнить действие, а не открыть прежний терминал. Для обычных программ аргументы передаются напрямую через `ProcessStartInfo.ArgumentList`, без shell-конкатенации. Командные строки могут содержать приватные сведения — JSON и логи остаются локальными и никуда не отправляются.

Недоступные EXE, окна повышенных процессов, приложения Store, несовпавшие окна и папки отображаются как частичное восстановление. Защита исходного снимка при этом остаётся. UNC проверяется в отдельном процессе с ограничением времени, затем повторяется через интервалы 5/15/30/60 секунд. Нельзя гарантировать foreground, если Windows запрещает смену фокуса.

## Данные и отказоустойчивость

```text
%LOCALAPPDATA%\WindowsWorkspaceBlackBox\
  settings.json
  logs\YYYYMMDD.log
  snapshots\YYYYMMDD_HHMMSS_fffffff_000.json
```

По умолчанию 100 снимков. Каждый пишется сразу в новый файл с `CreateNew` и сбросом на диск, без `snapshot.tmp` и без rename. Совпадения имени получают числовой суффикс. Оборванный/некорректный JSON пропускается при поиске последнего валидного снимка. Коррекция системных часов не вызывает перезаписи. Очистка работает в фоне; защищённый исходный снимок занимает одно место в лимите истории. При частичном восстановлении новые снимки не снимают защиту источника.

Сбор выполняется дочерним процессом с тайм-аутом; зависший COM/WMI не блокирует трей. Выход/завершение сеанса отменяют выполняемую работу. На заблокированном экране автоматический сбор приостанавливается. Второй экземпляр трея блокируется mutex текущего сеанса.

## Сборка

На Windows с .NET 10 SDK:

```powershell
dotnet restore WindowsWorkspaceBlackBox.slnx
dotnet build WindowsWorkspaceBlackBox.slnx -c Release --no-restore
dotnet test tests/WWBB.Tests/WWBB.Tests.csproj -c Release --no-build
dotnet publish src/WindowsWorkspaceBlackBox/WindowsWorkspaceBlackBox.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o artifacts/publish
```

Готовый файл: `artifacts/publish/WindowsWorkspaceBlackBox.exe`. GitHub Actions собирает и проверяет программу на Windows, выполняет тесты и сохраняет только этот EXE. Контрольная сумма SHA-256 выводится в журнал сборки. NSIS в автоматической сборке больше не используется. Шаги ручной приёмки: [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md).

WinForms, C#, JSON; HTTP, служба Windows и драйвер не требуются.
